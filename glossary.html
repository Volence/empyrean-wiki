Symbols & numbers

.emp
The source language of the Aeon engine: classic 68000 and Z80 instructions wrapped in a checked structure of modules, procedures and contracts, assembled by Sigil. Reading .emp1 · What .emp is
68000
The main CPU of the Genesis: a 16/32-bit Motorola processor at about 7.67 MHz. Game logic runs here. Genesis: The Machine1 · One machine, five parts

A

accumulator
The special register (A on the Z80) that most 8-bit arithmetic and logic operations read from and write their result back to. Z80: The Programming Model2 · The accumulator and the 8-bit registers
ASCII
A widely used table that gives each letter, digit, and symbol a number, so text can be stored as bytes. Numbers & Notation8 · Letters are numbers too
auto-increment
A VDP register holding a step that is added to the video memory address after every access, so a run of writes lands in consecutive places. Genesis: The VDP & Planes2 · Two ports and one command word

B

backdrop
The color the VDP shows wherever no plane or sprite pixel is drawn. One register picks it from any of the 64 color slots. Genesis: The VDP & Planes8 · Priority: one bit, seven layers
binary
Counting with only two digits, 0 and 1, the way digital hardware stores every value. Numbers & Notation2 · Binary
bit
The smallest piece of information: one of two values, usually written 0 or 1. Numbers & Notation1 · Bits, bytes, nibbles
block instruction
A Z80 instruction that copies or compares a run of bytes in one step, walking the pointer registers HL and DE and counting BC down; the repeating forms (ending in R, like LDIR) re-run themselves until the count reaches zero. Z80: Bits, Flow & Blocks7 · Block instructions
branch
An instruction that changes which instruction runs next, either always or only when a condition is true. A branch reaches its target by counting bytes forward or backward from itself. 68000: Flow3 · Conditions: what a branch actually tests
build shape
One of the several ROMs a single .emp source can produce, such as a plain release build or a debug build, chosen by build-time settings so each ROM carries only the code its shape asks for. Reading .emp6 · One source, several ROMs
bus
The shared set of wires carrying addresses and data between chips. Only one device can use a bus at a time, so anything else that wants it waits. Genesis: The Machine1 · One machine, five parts
bus arbiter
The chip that decides which processor gets a shared bus, and stalls the other one until the bus is free. Genesis: The Machine5 · Two processors, two worlds
byte
Eight bits: one unit of memory, holding a value from 0 to 255. Numbers & Notation1 · Bits, bytes, nibbles

C

comptime
Work the assembler does while building, before the ROM exists: values computed, code selected or generated, and checks run, none of which costs any bytes or cycles at run time. Reading .emp6 · One source, several ROMs
condition code
One of the bits the processor sets to describe the last result, such as whether it was zero or negative. A conditional instruction reads these bits rather than looking at the values themselves. 68000: The Programming Model2 · The status register and condition codes
contract
A machine-checked promise a procedure makes about the registers it changes, preserves and returns, and the conditions it needs. The assembler reads the body and holds the header to it, at warning tier or, for the provable clauses, at error tier. .emp: Contracts1 · The problem contracts solve
CRAM
Color RAM inside the VDP: 64 color slots of 9 bits each, arranged as four palettes of 16. What sits in CRAM defines every color on screen. Genesis: The Machine6 · The VDP and its three memories

D

DAC
The raw-sample channel on the FM chip: it plays recorded audio (like drums) one byte at a time, in place of FM channel six. Genesis: The Machine1 · One machine, five parts
dispatch
Choosing which routine to run by looking its address up at run time instead of naming it in the instruction. 68000: Flow4 · Dispatch: calling something computed
DMA
Direct Memory Access: the VDP copies data into video memory by itself, much faster than the CPU could. During a copy from 68000 memory the 68000 is paused; only VRAM fill and VRAM-to-VRAM copy run while the CPU keeps working. Genesis: The Machine6 · The VDP and its three memories
DTACK
The signal a device raises to tell the 68000 that a bus cycle has completed. Until it arrives the CPU waits, so a device that never raises it stalls the processor. Genesis: The Machine3 · The 68000's map of the world

E

exception
A forced detour: the CPU stops what it is doing, looks up an address in the vector table, and jumps there. Caused by hardware (an interrupt) or by the program itself (a trap, a bad instruction, a bad address). 68000: The Programming Model6 · Exceptions and when the PC goes wrong

F

flag
One bit in the flag register recording a fact about the last result, such as whether it came out zero, negative, or carried past the end of the byte. A conditional instruction reads a flag rather than looking at the value itself. Z80: The Programming Model4 · Flags and the AF save pair
flag register
A register whose individual bits each record a fact about the last result, such as whether it was zero or negative, so a later instruction can branch on it. Z80: The Programming Model4 · Flags and the AF save pair
frame pointer
An address register left pointing at a stack frame, so the routine can find its temporary values at fixed offsets even as the stack pointer moves. 68000: SystemLINK and UNLK

H

half-carry
A flag set when an add or subtract carries between bit 3 and bit 4 of a byte; the Z80 uses it to fix up binary-coded-decimal arithmetic. Z80: The Programming Model4 · Flags and the AF save pair
HBlank
The tiny gap at the end of each scanline. An interrupt can run here for per-line tricks like bending the background mid-screen. Aeon: The VDP & the Frame9 · The HBlank seam
hexadecimal
Counting in base 16, digits 0 to 9 then A to F. One hex digit is exactly four bits, so a byte is two hex digits. Numbers & Notation3 · Hexadecimal

I

immediate value
A constant written directly inside the instruction itself, rather than fetched from a register or memory. On the Z80 it is written as a plain number, like the 5 in ld a, 5. Z80: Loads & Arithmetic1 · How to read a Z80 instruction
index register
A 16-bit register (IX or IY on the Z80) that holds a base address, so an instruction can reach memory at that address plus a small signed offset. Z80: The Programming Model5 · Index registers
interrupt
A hardware signal that pauses the CPU, jumps it to a handler routine, and returns when the handler finishes. The Genesis uses interrupts to stay in step with the display. 68000: The Programming Model6 · Exceptions and when the PC goes wrong
interrupt mask
Three bits in the status register holding a single number from 0 to 7. The CPU ignores any interrupt at or below that level, so a mask of 0 permits everything and a mask of 7 blocks every ordinary interrupt; level 7 is non-maskable and can still get through. 68000: The Programming Model2 · The status register and condition codes
interrupt mode
One of three ways the Z80 can be set to respond to a maskable interrupt, chosen with IM 0, IM 1, or IM 2. The Genesis uses IM 1, where an interrupt always jumps to the fixed address $0038. Z80: Bits, Flow & Blocks6 · Waiting and interrupts

J

jump table
A list of addresses held in memory, one per case, that code indexes into so it can jump to the entry matching a value it is holding. 68000: Flow4 · Dispatch: calling something computed

M

master clock
The single oscillator every other clock in the console is divided down from, which is why all the parts stay in step with each other. Genesis: The Machine2 · One crystal, every clock
memory map
The list of what answers at each address. One address bus reaches ROM, RAM, the video chip and the controller ports, and the map says which is which. Genesis: The Machine3 · The 68000's map of the world
mirror
An address range that answers as a copy of another one, because the hardware decodes only some of the address lines. Genesis: The Machine3 · The 68000's map of the world
module
One .emp file, and the unit the language scopes names in: everything it declares is private to it unless marked public, and it names which section of the ROM its code belongs to. Reading .emp2 · A real file, top to bottom

N

nametable
A grid map in VRAM saying which tile to draw in each 8x8 cell of a plane, plus that cell's palette, flip and priority bits. Genesis: The VDP & Planes4 · A plane is a grid of words
nibble
Four bits, half a byte: exactly one hexadecimal digit, with 16 possible values. Numbers & Notation1 · Bits, bytes, nibbles

O

opcode
The byte or bytes that name one instruction to the CPU. It is what the assembler turns a line of your source into, and what the processor fetches and executes. No page teaches this one yet
open bus
What you read from an address nothing is wired to. On a Genesis it is the top byte of the instruction the 68000 was about to fetch, with a zero byte under it. Not an error, which is exactly the problem. Genesis: The Machine3 · The 68000's map of the world
operand
The value an instruction works on. Most 68000 instructions take a source operand (read from) and a destination operand (written to); an addressing mode is how each one says where its value lives. 68000: Addressing Modes1 · How an instruction names its operand

P

palette
A set of 16 colors in CRAM. Every tile and sprite picks one of the four palettes. Aeon: The VDP & the Frame1 · What the VDP draws with
plane
One of the scrolling tile layers the VDP draws. A plane is a grid of cells, and each cell names the tile to draw there. Genesis: The VDP & Planes4 · A plane is a grid of words
priority
One bit on a nametable cell or a sprite choosing which of two draw layers it belongs to. It is not a depth value, and two cells of the same plane can differ. Genesis: The VDP & Planes8 · Priority: one bit, seven layers
privileged instruction
An instruction the 68000 will only execute in supervisor mode. Attempting one in user mode raises an exception instead. STOP, RESET, MOVE to SR and MOVE USP are all privileged. 68000: The Programming Model2 · The status register and condition codes
program counter
The 16-bit register on the Z80 that holds the address of the next instruction to fetch; it advances past each instruction as that instruction runs, and jumps, calls and returns redirect it. 68000: The Programming Model3 · The program counter and labels
PSG
The Programmable Sound Generator: a simple chip with three square-wave tone channels and one noise channel. Genesis: The Machine1 · One machine, five parts

R

read-modify-write
A single instruction that reads a location, changes the value, and writes it back. Many 68000 instructions do this; TAS is the only one that holds the bus for the whole sequence, and the Genesis does not honour its write. Genesis: The VDP & Planes3 · The hazard: instructions that read before they write
register
A small storage slot inside a chip. CPU registers (d0-d7, a0-a7) hold the values being worked on; VDP registers configure how the video chip behaves. 68000: The Programming Model1 · The register file
register (Z80)
A small storage slot inside a chip. CPU registers (on the Z80: A, B, C, D, E, H, L, F, and the 16-bit IX, IY, SP, PC) hold the values being worked on; VDP registers configure how the video chip behaves. Z80: The Programming Model1 · The Z80 at a glance
register pair
Two 8-bit registers treated together as one 16-bit register, like B and C forming BC. Z80: The Programming Model3 · Fixed register pairs and pointers
registers (Z80)
A small storage slot inside a chip. CPU registers (on the Z80: A, B, C, D, E, H, L, F, and the 16-bit IX, IY, SP, PC) hold the values being worked on; VDP registers configure how the video chip behaves. Z80: The Programming Model1 · The Z80 at a glance
return address
The address of the instruction that should run next once a called routine has finished. A call writes it onto the stack and the return instruction reads it back. 68000: Flow1 · Returning, the dumb version

S

SAT
The Sprite Attribute Table: the list in VRAM describing every sprite's position, size, tiles and drawing order. Aeon: The VDP & the Frame1 · What the VDP draws with
scanline
One horizontal line of the picture. NTSC draws 262 per frame (224 visible); PAL draws 313. Genesis: The Machine7 · A tour of one frame
shadow register set
A duplicate set of the main registers (written with a prime, like BC') that the Z80 can swap in with a single instruction, mainly for fast interrupt handling. Z80: The Programming Model7 · Alternate registers
Sigil
The from-scratch assembler that turns .emp source into Genesis ROM bytes for both of the console's CPUs, and checks the contracts the language adds. Reading .emp1 · What .emp is
sprite
A movable image drawn independently of the background planes, built from tiles. The hardware handles up to 80 at once. Aeon: The VDP & the Frame1 · What the VDP draws with
stack frame
A block of memory a routine carves out of the stack for its own temporary use, and releases when it returns. LINK opens one and UNLK closes it. Hand-written Genesis code usually keeps its values in registers and fixed RAM instead, so frames are rare. 68000: SystemLINK and UNLK
stack pointer
The 16-bit register on the Z80 that points at the top of the stack: PUSH decrements it then writes, POP reads then increments it. Z80: The Programming Model6 · Stack and control flow
status register
A 16-bit register holding the CPU's own state. Its low byte is the condition codes (X N Z V C) that ordinary instructions set; its high byte is the supervisor half, holding the trace bit, the supervisor bit, and the interrupt mask. 68000: The Programming Model2 · The status register and condition codes
subroutine
A block of instructions that other code calls and that hands control back when it finishes, so the same work can be reused from many places. 68000: Flow1 · Returning, the dumb version
supervisor mode
The 68000's privileged state. In supervisor mode all instructions are allowed and the CPU uses its own stack pointer. A Genesis cartridge runs in supervisor mode the whole time, because there is no operating system to drop it into user mode. 68000: The Programming Model2 · The status register and condition codes

T

T-state
The Z80's basic clock tick, one cycle of its clock. Every instruction's timing is measured in T-states, so a 4 T-state instruction takes four ticks. On the Genesis the Z80 runs at about 3.58 MHz, so a tick is roughly a quarter of a microsecond. Z80: Loads & Arithmetic1 · How to read a Z80 instruction
tail call
Ending a routine by jumping to another routine instead of calling it, so that when the second one finishes it hands control straight back to whoever called the first. 68000: Flow5 · The tail call, and other deliberate abuse
tile
An 8x8 pixel image, 4 bits per pixel (16 colors), 32 bytes. Everything the VDP draws is built from tiles. Aeon: The VDP & the Frame1 · What the VDP draws with
TMSS
The Trademark Security System on later consoles: boot must write the ASCII letters SEGA to a magic address, or the next video access locks the machine. Aeon: Boot & Hardware Init2 · Proving we're a licensed game
trap
A deliberate exception raised by the program rather than by hardware, using the TRAP instruction. Intended as the way a program asks an operating system for something. Genesis games do not use it that way. 68000: SystemTRAP
two's complement
The standard way to store signed numbers in a fixed width: the top bit carries negative weight, so every bit pattern is a distinct number and there is a single zero. Numbers & Notation7 · Signed numbers and two's complement

U

user mode
The 68000's restricted state, meant for programs an operating system does not trust. Privileged instructions are refused. Genesis games effectively never run in it. 68000: The Programming Model2 · The status register and condition codes

V

VBlank
The vertical blanking interval: the short window between frames while nothing is being drawn. The only safe time for bulk video updates, and where a game does almost all of its time-critical video work. Genesis: The Machine7 · A tour of one frame
VDP
The Video Display Processor, the Genesis graphics chip. It draws planes and sprites from its own 64KB of video memory; the CPU talks to it through two ports. Genesis: The VDP & Planes1 · The chip that owns its own memory
vector table
The table at the very start of memory holding the addresses the CPU jumps to when an exception happens, one four-byte slot each. The 68000 defines 256 of them, but a Genesis game uses only the first 64, which is why the cartridge header begins at $100. 68000: The Programming ModelWhich slot is which
VRAM
The VDP's private 64KB of video memory holding tile art, nametables and the sprite table. The CPU cannot address it directly; everything goes through the VDP ports or DMA. Genesis: The Machine6 · The VDP and its three memories
VSRAM
Vertical Scroll RAM inside the VDP: the per-plane (and per-two-cell-column) vertical scroll values. Genesis: The VDP & Planes7 · Scrolling vertically: VSRAM

W

Window plane
A third tile layer that never scrolls and takes over a rectangle of the screen from plane A. Genesis: The VDP & Planes9 · The Window: the plane that replaces plane A
work RAM
The 68000's 64KB of general-purpose memory at $FF0000-$FFFFFF. Most CPU-visible runtime state lives here; graphics and sound state live in the VDP's VRAM/CRAM/VSRAM and the Z80's RAM. Genesis: The Machine3 · The 68000's map of the world

Y

YM2612
The six-channel FM synthesizer chip that gives the Genesis its signature sound. Channel six can play raw samples instead (the DAC). Genesis: The Machine1 · One machine, five parts

Z

Z80
The second, smaller CPU: 8-bit, about 3.58 MHz, with its own memory and its own bus. On a Genesis it conventionally runs the sound driver. Genesis: The Machine5 · Two processors, two worlds
